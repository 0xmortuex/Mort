# Mort standard library reference

One paragraph per bundled `std` module, covering its public surface. Each
module is a single `.mx` file under `std/`; import it with its module path
(e.g. `import std.strings;`) and call functions through the last path
segment (e.g. `strings.trim(...)`). This reference is generated by hand
against the module sources under `std/` — if a function's behavior looks
wrong here, the source is the ground truth.

## `std.algorithm`

Generic slice helpers with no caller-supplied comparator: `reverse<T>(values: []T)`
reverses in place, `sort<T>(values: []T)` is an in-place insertion sort
requiring `T` to support `<`, and `index_of<T>` / `contains<T>` do a linear
scan over `[]const T` for a needle, returning `Option<u64>` and `bool`
respectively. For element types without a built-in `<` (or where the caller
wants a custom order), see `std.sort`, which takes an explicit comparator.

## `std.ascii`

Byte-level ASCII classification and case conversion, all operating on `u8`
(not on multi-byte UTF-8 sequences): `is_alpha`, `is_digit`, `is_space`,
`to_upper`, `to_lower`. `upper_inplace(text: []u8)` and
`lower_inplace(text: []u8)` apply the corresponding conversion to every byte
of a mutable slice in place.

## `std.atomic`

A single atomic 64-bit signed integer, `AtomicI64` (a `resource struct`
wrapping an opaque handle). `new_i64(initial)` creates one; `load`, `store`,
`exchange`, `fetch_add`, `fetch_sub`, and `compare_exchange` operate on a
`*AtomicI64`; `destroy` releases the underlying handle and must be called
exactly once per value.

## `std.bytes`

Raw byte-slice operations: `fill(output: []u8, value: u8)` and
`zero(output: []u8)` (fill with 0) write every byte of a mutable slice;
`copy(destination: []u8, source: []const u8)` copies up to
`min(destination.len, source.len)` bytes and returns the count copied;
`equal(left: []const u8, right: []const u8)` does a length-then-byte-by-byte
comparison.

## `std.crypto`

Cryptographically secure random bytes via the runtime's `secure_random_fill`:
`random_fill(buffer: *u8, length: u64)` fills a raw buffer and returns
whether it succeeded, and `random_u64()` returns a full random `u64` (via an
`assert`ed 8-byte fill).

## `std.env`

Two thin wrappers over the C library's `getenv`: `get(name: *u8) -> *u8`
returns the raw environment value pointer (null if unset), and
`exists(name: *u8) -> bool` reports whether the variable is set.

## `std.fs`

Buffered file I/O over a `File` struct wrapping a C `FILE*`-style handle:
`open(path, mode)` opens a file with a C-style mode string (e.g. `"r"`,
`"w"`), `is_open` checks the handle is non-null, `read`/`write` transfer into
or out of a `[]u8`/`[]const u8` buffer and return the byte count moved,
`flush` flushes buffered writes, and `close` closes the handle and clears it
(safe to call on an already-closed `File`).

## `std.map`

A generic open-addressing-free association array, `Map<Key, Value>` (a
`resource struct` backed by two parallel heap arrays), with `Key` compared
by `==` in a linear scan — so it is best suited to small maps or types with
cheap equality. `new<Key, Value>()` / `with_capacity<Key, Value>(capacity)`
construct one; `insert` adds or overwrites a key (returning `true` only for
a new key — an overwrite of a resource `Value` still requires the caller to
have drained the old value first, since the slot is overwritten as raw
memory); `get` returns `Option<Value>`; `contains` checks key presence;
`remove` deletes a key and returns its `Value` (moved out, so a resource
`Value` is not dropped) inside `Option<Value>`, `Option<Value>.None` if the
key was absent, shifting later entries down to fill the gap; `key_at` /
`value_at` return the entry at a given index (aliasing copies, same caveat as
`get`) as `Option<Key>` / `Option<Value>`, `None` if the index is
out-of-bounds — the supported way to enumerate a map's entries in insertion
order (`for index: u64 in 0..map.length { ... }`) without reaching into the
struct's internal fields; `find_by` scans entries in insertion order and
returns the `Option<Key>` of the first one for which a caller-supplied
`fn(Key, Value) -> bool` predicate is true (`None` if none match, same
aliasing-copy caveat as `key_at`/`value_at`), for a predicate search without
a hand-rolled loop; `reserve` grows capacity ahead of time; `is_empty`
checks whether the length is zero; `clear` resets the length without freeing
backing storage; `destroy` frees both backing arrays.

## `std.math`

Generic numeric helpers usable with any type supporting the relevant
operators: `min<T>`, `max<T>`, `clamp<T>(value, minimum, maximum)`,
`abs<T>` (via `0 - value`, so unsigned `T` will wrap rather than error),
`gcd<T>` (iterative Euclidean algorithm), and `pow<T>(base, exponent: u64)`
(binary exponentiation, `exponent` is always unsigned).

## `std.memory`

Private (non-`pub`) byte-buffer primitives used internally by other modules:
`mem_set`, `mem_copy`, and `mem_equal` operate on raw `*u8` pointers with an
explicit count rather than slices. Not part of the public API — prefer
`std.bytes` for slice-based equivalents.

## `std.mutex`

A single OS mutex, `Mutex` (a `resource struct` wrapping an opaque handle).
`new()` creates one; `lock` and `unlock` take a `*Mutex` and `assert` that
the underlying call succeeded; `destroy` releases the handle and must be
called exactly once per value.

## `std.option`

Defines the `Option<T>` enum (`Some(T)` / `None`) used throughout the
standard library for values that may be absent. No functions — just the
type declaration.

## `std.owned_string`

A heap-allocated, null-terminated, owned byte string, `String` (a
`resource struct`). `from(text: *u8)` copies a C string into a new owned
buffer; `concat(left, right)` allocates a new `String` holding the
concatenation of two existing ones; `view(value: *String) -> []const u8`
borrows the contents as a slice without copying; `destroy` frees the
backing buffer. Every `String` returned by `from` or `concat` must eventually
reach `destroy` exactly once.

## `std.process`

Two `extern`-backed process controls: `run(command: *u8) -> c_int` shells
out via the C library's `system()` and returns its exit status, and
`terminate(status: c_int)` calls C's `exit()` immediately (does not return,
does not run destructors).

## `std.random`

A non-cryptographic xorshift64 PRNG, `Random` (plain struct holding a
`u64` seed/state — not a `resource`, no `destroy` needed).
`seeded(seed: u64)` constructs one (a zero seed is replaced with a fixed
nonzero constant, since xorshift cannot recover from an all-zero state);
`next_u64` advances the generator and returns the next value; `next_u32`
takes the high 32 bits of a `next_u64` call; `below(random, maximum)`
returns a value in `[0, maximum)` via modulo (not uniformly unbiased for
non-power-of-two `maximum`); `between(random, minimum, maximum)` returns a
value in `[minimum, maximum)`; `fill(random, output: []u8)` fills a buffer
byte-by-byte from successive `next_u64` calls. For security-sensitive
randomness, use `std.crypto` instead.

## `std.result`

Defines the `Result<Value, Error>` enum (`Ok(Value)` / `Err(Error)`) used
for fallible operations. No functions — just the type declaration.

## `std.sort`

An in-place, stable insertion sort taking a caller-supplied `less_than`
comparator, so — unlike `std.algorithm.sort` — it works for any element
type `T`, including structs with no built-in `<`. `sort<T>(values: []T,
less_than: fn(T, T) -> bool)` sorts in place (O(n) best case, O(n^2) average
and worst case, O(1) extra space); `is_sorted<T>(values: []const T,
less_than)` checks whether a slice is already ordered.

## `std.string`

Private (non-`pub`) null-terminated C-string helpers: `str_len`,
`str_equal`, `str_copy` (copies until the source's null terminator and
writes one to the destination, returning the length copied). Not part of
the public API.

## `std.strings`

Slice helpers over `[]const u8` text (UTF-8 agnostic — all operations are
byte-oriented). `equal`, `starts_with`, `ends_with` do straightforward byte
comparisons; `index_of(text, needle)` returns the first byte offset of
`needle` as `Option<u64>` (an empty `needle` matches at offset 0);
`trim(text)` strips leading/trailing ASCII whitespace and returns a
borrowed view (no copy); `parse_u64` / `parse_i64` parse a decimal integer
(with optional leading `-` for the signed variant), returning `None` on
empty, sign-only, or non-digit input; `split(text, separator)` returns a
`Vec<[]const u8>` of views borrowed from `text`, matching Python's
`str.split(sep)` semantics — consecutive or edge separators produce empty
elements, and an empty `separator` returns the whole text as a single
unsplit element. `replace(text, old, new)` returns a freshly allocated
`std.owned_string.String` with every non-overlapping, left-to-right
occurrence of `old` replaced by `new` (replace-all, like Python's
`str.replace` with no `count`; an empty `old` returns an unchanged owned
copy rather than inserting `new` between every byte). `count(text, needle)`
counts non-overlapping, left-to-right occurrences of `needle` in `text` as a
plain `u64`, using the same matching pass as `replace`'s counting loop (a
match is not rescanned, so `count("aaaa", "aa")` is 2, not 3); an empty
`needle` returns 0, unlike Python's `str.count("")`, which returns
`text.len + 1`. `join(parts, separator)`
is `split`'s inverse: it takes a `*Vec<[]const u8>` and concatenates its
elements with `separator` inserted between consecutive ones, matching
Python's `separator.join(parts)` (zero elements yields an empty string, one
element yields an unchanged copy with no separator inserted), also
returning a freshly allocated `std.owned_string.String`. `contains(text,
needle)` is a thin wrapper over `index_of(text, needle)` that returns a
plain `bool`. `trim_start(text)` and `trim_end(text)` are `trim`'s one-sided
counterparts, stripping ASCII whitespace from only the leading or only the
trailing edge respectively and returning a borrowed view, same as `trim`.
`repeat(text, count)` returns a freshly allocated `std.owned_string.String`
containing `text` repeated `count` times, matching Python's `text * count`
(`count == 0` returns an empty owned string). `last_index_of(text, needle)`
is `index_of`'s reverse counterpart: it returns the *last* byte offset of
`needle` as `Option<u64>`, scanning from the end so the rightmost occurrence
wins (an empty `needle` matches at `text.len`, the last possible start
position, mirroring `index_of`'s empty-needle match at offset 0). Every view
returned by `trim`, `trim_start`, `trim_end`, or `split` borrows from the
original `text` buffer and is only valid as long as it is (`index_of` and
`last_index_of` return a byte offset into `text` rather than a view, but
the same lifetime applies to interpreting it). `split_once(text, separator)`
returns `Option<SplitOnce>`, a struct of two borrowed views (`before` and
`after` the first `separator` match), or `None` if `separator` does not
occur — the cheaper alternative to `split` when a caller only needs the
first two parts (e.g. `"key=value"`), since it borrows two views instead of
allocating a `Vec`. Like `index_of`, an empty `separator` matches at offset
0 (`before` empty, `after` all of `text`). `rsplit_once(text, separator)` is
`split_once`'s reverse counterpart: it also returns `Option<SplitOnce>`, but
split at the *last* `separator` match (built the same way `last_index_of`
mirrors `index_of`), useful for e.g. peeling a file extension or the last
path segment off `text`. Like `last_index_of`, an empty `separator` matches
at the last possible position, `text.len` (`before` all of `text`, `after`
empty). `from_u64(value)` and `from_i64(value)` are `parse_u64`/`parse_i64`'s
inverse: each returns a freshly allocated `std.owned_string.String`
containing `value`'s decimal digits, with a leading `-` for a negative
`from_i64` value (`value == 0` returns `"0"` for both). `from_i64` computes
the magnitude of a negative value via two's-complement negation in `u64`
space (`~(value as u64) + 1`) rather than signed negation, so it is correct
even for `value == i64::MIN`, whose magnitude (2^63) has no positive `i64`
representation to negate into. `to_hex(value)` formats a `u64` as lowercase
hexadecimal digits (no `"0x"` prefix, no leading zeros; `value == 0` returns
`"0"`), also returning a freshly allocated `std.owned_string.String`.
`replace`, `join`, `repeat`, `from_u64`, `from_i64`, and `to_hex` are the
only functions here that allocate, so the caller must call
`std.owned_string.destroy` on their results.

## `std.thread`

Raw OS thread spawning, `Thread` (a `resource struct` wrapping an opaque
handle) with a `Callback = fn(*void) -> i64` entry point.
`spawn(callback, context)` starts a thread; `join` waits for it to finish
and returns its result (clears the handle so a `Thread` can only be joined
once); `sleep_millis(duration)` blocks the calling thread; `destroy` joins
an unjoined thread as a safety net (discarding its result) so a `Thread`
going out of scope doesn't leak the handle. For a pool of threads managed
together with bulk cancellation, see `std.task`.

## `std.task`

A group of raw OS threads managed together, `TaskGroup` (a `resource
struct` holding a dynamic array of thread handles plus a shared atomic
cancellation flag). `new()` creates an empty group; `spawn(group, callback,
context)` starts a thread and adds it to the group, refusing to start new
work once `cancel` has been called (returns `false`); `cancel` sets the
shared flag (callbacks must poll `cancelled` themselves — cancellation is
cooperative, not preemptive); `cancelled` and `count` are read-only queries;
`join_all` waits for every spawned thread and returns the sum of their
results, then clears the group so it can be reused for another batch;
`destroy` cancels, joins everything outstanding, and frees the group's
backing storage.

## `std.time`

Two clock readings: `unix_seconds() -> i64` (wall-clock Unix timestamp) and
`cpu_milliseconds() -> u64` (a monotonic process/CPU-time counter, not tied
to wall-clock time — suitable for measuring elapsed durations).

## `std.vec`

A generic growable array, `Vec<T>` (a `resource struct` backed by a heap
array that doubles on growth), safe for both plain and resource element
types. `new<T>()` / `with_capacity<T>(capacity)` construct one; `push`
appends (moving a resource `T` into the backing slot); `get` returns an
**aliasing copy** as `Option<T>` — not safe to rely on for resource
elements, since it duplicates ownership; `set` overwrites a slot in place
(the caller must have already drained a resource `T` previously stored
there); `pop` removes and returns the last element as `Option<T>`;
`remove(vec, index)` removes an arbitrary element, moving its value out as
`Option<T>` and shifting later elements down to fill the gap (returns
`None` and leaves the vector unchanged for an out-of-bounds `index`);
`insert(vec, index, item)` is `remove`'s counterpart — it moves `item` into
an arbitrary position, growing the backing array if needed and shifting
later elements up to open a gap (`index == length` appends, same as `push`;
an out-of-bounds `index` returns `false` and leaves the vector unchanged,
so the caller must otherwise drop or reuse `item`); `index_of(vec, item)`
scans in order and returns the index of the first element equal to `item`
as `Option<u64>` (`None` if none match), reading elements via the same
aliasing copy as `get`; `contains(vec, item)` is a thin wrapper over
`index_of`; `first(vec)` / `last(vec)` are thin wrappers over `get(vec, 0)`
/ `get(vec, length - 1)` that return `Option<T>` (`None` for an empty
vector), sharing `get`'s aliasing-copy caveat for resource elements;
`as_slice` /
`as_const_slice` borrow the live contents as `[]T` / `[]const T` without
copying; `swap(vec, i, j)` exchanges two elements in place by moving each
slot's value out and back in exactly once (safe for resource elements,
unlike `get`/`set`; returns `false` and leaves the vector unchanged if
either index is out of bounds, `true` as a no-op when `i == j`); `is_empty`
checks whether the length is zero; `clear` resets the length without
freeing backing storage; `destroy` frees the backing array only — it does
**not** drop resource elements still in the vector, so a `Vec` of resources
must be drained (e.g. by repeated `pop`/`remove`) before `destroy`.

## `std.map` and `std.vec`: resource caveats

Both containers' `get`/`set` (and `Map`'s overwrite-on-`insert`) operate on
raw backing storage rather than through the ownership checker, so they only
fully track resource lifetimes through `push`/`Vec.insert`-then-`pop`/
`drain`/`remove` patterns (`Map.remove`, `Vec.remove`, and `Vec.insert` all
move their slot's value in or out cleanly, same as `Vec.pop`). See the
"Resource-aware container API" item in `BACKLOG.md` for the remaining gap
(`get`/`set`/`Map.insert`-overwrite) and the planned `get_ref`/dropping-
`destroy` API.

## `std.json`

A JSON parser and serializer built on a flat arena (`Document`, a `resource
struct`): every value is a plain-data `Node` in one `Vec<Node>`, array/object
children are a linked list in one `Vec<Child>`, and all string bytes (values
and object keys) live in one `Vec<u8>` byte pool — so nothing nested owns a
resource, keeping the whole structure inside Mort's ownership model.
`parse(text: *const u8, length: u64)` / `parse_cstr(text: *const u8)` parse
input into a `Document`; `ok(doc)` reports success and `error_pos(doc)`
gives the byte offset of a parse failure. Given a `Document` and a node
index (start from `root(doc)`): `kind`, `is_null`/`is_bool`/`is_number`/
`is_string`/`is_array`/`is_object` inspect a node; `as_bool`/`as_number`/
`as_string` extract a scalar's value; `array_len`/`array_get` and
`object_len`/`object_key`/`object_value_at` walk array elements and object
entries by position; `object_get_view`/`object_get` look up an object entry
by key (a `[]const u8` view or a C string, respectively), returning
`Option<u64>`; `object_get_path(doc, index, "a.b.c")` walks a dotted path
through nested objects in one call. `stringify(doc, index)` serializes a
node back to a `Vec<u8>`. `destroy(doc)` frees the three backing arenas.
Note: `std.json` does not validate UTF-8 in string values — invalid bytes
parse "successfully" and are copied verbatim into the string pool (see the
"Larger" section of `BACKLOG.md`).

## `std.net`

Raw TCP/UDP sockets, `Socket` (a `resource struct` wrapping an opaque OS
handle). `tcp_connect`/`tcp_listen`/`accept` and `udp_connect`/`udp_bind`
set up connections; `send`/`send_all`/`receive`/`receive_exact` transfer
raw bytes (the `_all`/`_exact` variants loop until the full length is
moved or a hard failure occurs); `send_to`/`receive_from` are the
address-carrying UDP variants; `shutdown` half-closes a socket;
`set_nonblocking` toggles blocking mode; `wait`/`wait_readable`/
`wait_writable` poll with a millisecond timeout; `would_block()` checks the
last operation's error against EWOULDBLOCK/EAGAIN; `local_port` reads back
the bound port; `destroy` closes the underlying handle.

## `std.tls`

A TLS client connection, `Stream` (a `resource struct` wrapping an opaque
handle), layered similarly to `std.net`. `connect(hostname, port)` connects
using the system's default trust store; `connect_with_ca(hostname, port,
ca_data, ca_length)` connects against an explicit in-memory CA certificate
instead; `send`/`send_all`/`receive`/`receive_exact` transfer bytes over the
encrypted channel; `protocol_version` reports the negotiated TLS version;
`destroy` closes the handle.

## `std.http`

Plaintext HTTP/1.1 building blocks over a `std.net.Socket`, mostly
low-level parsing helpers plus one convenience call. `find_header_end`
locates the blank line ending a header block; `content_length` and
`header_value` extract specific header data from raw response bytes;
`status_code` parses the numeric status from a status line;
`framed_length` determines how much of a buffered response is a complete
message; `build_request`/`write_request` construct and send a request line
plus headers; `write_response` sends a response; `read_message` reads a
full HTTP response (following `Content-Length` framing) into a buffer;
`read_headers` reads byte-by-byte until the header block ends. `get(host,
port, target, buffer, capacity)` is the one-call convenience wrapper: opens
a TCP connection, sends a `GET`, and reads the response into `buffer`,
returning the byte length or a negative value on failure.

## `std.https`

The TLS counterpart to `std.http`, reusing `std.http`'s request-building and
response-framing logic over a `std.tls.Stream` instead of a plaintext
socket. `write_request` builds a request via `std.http.build_request` and
sends it with `std.tls.send_all`; `read_message` reads a full response
using the same framing rules as `std.http.read_message`; `get(host, port,
target, buffer, capacity)` connects with the system trust store and issues
a `GET`; `get_with_ca(..., ca_data, ca_length)` is the same but against an
explicit CA certificate.

## `std.websocket`

RFC 6455 WebSocket framing and handshakes over a `std.net.Socket`.
`accept_key(client_key, key_length, output, capacity)` computes the
`Sec-WebSocket-Accept` value from a client's key (SHA-1 + the WebSocket
GUID, base64-encoded). `client_handshake(socket, host, target, response,
response_capacity)` sends the upgrade request with a random key and
validates the server's `101` response and accept-key echo.
`server_handshake(socket, request, request_capacity)` reads and validates
an incoming upgrade request. `send(socket, client_side, opcode, payload,
length)` writes one frame — masking the payload when `client_side` is true,
per the spec, and rejecting invalid opcodes, oversized control frames, or
(for text/close frames) invalid UTF-8/close-code payloads. `receive(socket,
expect_masked, output, capacity, opcode)` reads one frame and reports its
opcode through the out-parameter.
