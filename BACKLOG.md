# Backlog

Real, finishable improvements — the daily agent picks ONE and ships it end-to-end.
Rules: check items off when done, add follow-ups you discover, never do two at once,
smallest reviewable change wins.

**Safety:** Mort is a real, well-tested language. The daily agent works only on
**verifiable, low-risk surface** — new `std` modules, docs, examples, and tests —
and runs the relevant tests before pushing (`pip install ziglang`, then a targeted
`pytest` and/or `python mortc.py --run` on a small program). It does **not** change
the compiler internals (`mort/parser.py`, `mort/typechecker.py`, `mort/codegen.py`)
autonomously; those need careful human review with the full suite.

- [x] `std.strings` follow-up: `split(text, separator)`. Shipped 2026-08-01: `std/strings.mx` adds `split(text: []const u8, separator: []const u8) -> Vec<[]const u8>`, returning views borrowed from `text` (no copies, checked against `std.vec` — `Vec<[]const u8>` works fine since slices aren't resources). Matches Python's `str.split(sep)`: consecutive/edge separators yield empty elements, an empty separator returns the whole text as one element. Covered by `test_std_strings_split_borrows_views_and_matches_python_semantics` in `tests/test_mort.py` (9 assertions incl. no-match, empty-separator, and leading/trailing-separator cases, `--run` exits 0), full suite (337 tests) green, version bumped to 0.54.0.
- [x] `std.strings` follow-up: `replace(text, old, new)`. Shipped 2026-08-03: `std/strings.mx` adds `replace(text: []const u8, old: []const u8, new: []const u8) -> std.owned_string.String`, returning a freshly allocated, null-terminated owned buffer (the result length generally differs from the input, so unlike `split` it can't return borrowed views); the caller owns the result and must call `std.owned_string.destroy` on it. Replace-all, like Python's default: matches are found left-to-right and non-overlapping (a match is not rescanned once consumed, so `"aaaa".replace("aa","b")` is `"bb"`, not `"bab"`). An empty `old` returns an unchanged owned copy of `text`, consistent with `split`'s treatment of an empty separator, rather than Python's insert-between-every-byte behavior. Covered by `test_std_strings_replace_builds_owned_buffer_and_matches_python_semantics` in `tests/test_mort.py` (6 assertions: basic replace-all, no-match, overlapping-match non-rescanning, empty-`old`, grow-on-longer-replacement, and whole-text-is-the-match, `--run` exits 0), full suite (338 tests) green, version bumped to 0.55.0.

- [ ] `std.strings` follow-up: `replace` is replace-all only; a `count`-limited or first-occurrence-only variant (`Vec.split`-style Python has `str.replace(old, new, count)`) might be worth adding if a caller needs it — no evidence of demand yet, so not worth doing speculatively.

## Larger (sketch in the item before shipping — may need human review)
- [ ] Resource-aware container API: `Vec.get` returns an aliasing copy (unsafe for resource elements) and `Vec.destroy` frees only the backing array. Design a safe `get_ref` returning `*T` and an element-dropping destroy without breaking the plain-`T` API. Note (found while writing `docs/stdlib.md` 2026-08-02): `std.map`'s `Map.get` and `Map.insert`'s overwrite-of-an-existing-key path have the identical aliasing-copy / no-drop gap for a resource `Value` — worth folding into the same design rather than a separate pass.
- [ ] `std.random.below(random, maximum)` uses `next_u64(random) % maximum`, which is not uniformly unbiased when `maximum` doesn't evenly divide 2^64 (modulo bias, more pronounced for large `maximum`). Worth a doc note today in `std/random.mx`'s header at minimum; an unbiased variant (rejection sampling) is a possible follow-up if any caller needs uniformity guarantees — `std.random` is already documented as non-cryptographic, so this may not be worth fixing.
- [ ] `std.json` currently never validates UTF-8 in string values (confirmed 2026-07-31: a raw `0xFF` byte parses "ok" and is copied verbatim into the pool). Worth an explicit doc note in the `std/json.mx` module header today, and a possible opt-in strict-mode validation pass later — needs a design sketch for the error-reporting story (byte offset of the first invalid sequence) before it's a same-day task.
